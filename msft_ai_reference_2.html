Section 01
Data Platform — The Foundation Layer
The infrastructure that stores, processes, and governs data at scale. Every AI and agentic workload sits on top of this. Get this wrong and the entire AI programme fails.
The Microsoft data platform story converged in 2023 into a single answer: Microsoft Fabric. Before Fabric, clients had to stitch together Azure Synapse, Azure Data Factory, Power BI, and Azure Databricks into pipelines. Now those workloads share a single storage layer — OneLake — which eliminates data movement and the integration complexity that used to consume most of the engineering budget.
Microsoft Fabric
Unified SaaS Analytics Platform
The single answer to "which Azure data platform?" Built on OneLake — one logical storage layer that all workloads share. Combines Data Engineering (Spark notebooks, pipelines), Data Warehousing (SQL endpoint), Data Science (ML experiments), Real-Time Intelligence (event streaming), and Power BI into one SaaS interface. No data movement between tools. DirectLake connects Power BI directly to OneLake without import or refresh cycles.
Agentic relevance: The Gold layer of Fabric is where data products live — the governed, quality-assured datasets that feed RAG applications, feature stores, and agentic memory systems. The self-serve layer (notebooks, SQL endpoint) enables Data Analyst agents to query live data.
All industries Foundation platform Preferred: FSI, Retail, Healthcare
Azure Data Lake Storage Gen2 (ADLS)
Scalable Object Storage
Hierarchical namespace object storage that underpins Fabric's OneLake and standalone data lake architectures. Stores raw, Bronze, and Silver zone data in open formats (Parquet, Delta, JSON). RBAC and ACL security at file and folder level.
When still used standalone: When Fabric is not yet adopted, or when a client has existing Databricks architecture where ADLS serves as the storage layer beneath Unity Catalog.
Storage layer Legacy / Databricks stacks
Azure Synapse Analytics
Integrated Analytics Service (Legacy Path)
The predecessor architecture to Fabric — combines SQL data warehouse (Dedicated/Serverless SQL Pool), Spark processing, and data integration (Synapse Pipelines) in one workspace. Still widely deployed in existing enterprise estates.
Recommended approach: For new programmes, use Fabric. For existing Synapse deployments, the migration path is Fabric Warehouse (SQL workloads) and Fabric notebooks (Spark workloads). Synapse continues to receive support but is not the strategic investment direction.
Migration target → Fabric FSI, Government
Azure Data Factory (ADF)
Data Orchestration & ETL / ELT
Cloud-native ETL/ELT service with 100+ connectors to SaaS, on-prem, and cloud sources. Manages pipeline scheduling, monitoring, and dependency management. In Fabric, the equivalent is Fabric Data Pipelines — same paradigm, native SaaS experience. ADF remains relevant for hybrid (on-prem to cloud) ingestion scenarios.
Agentic relevance: ADF pipeline events are the source triggers for agentic monitoring systems — precisely the pattern in the LangGraph pipeline monitoring asset. Azure Event Grid bridges ADF pipeline completion events to Event Hubs for real-time agent consumption.
Ingestion layer Hybrid / on-prem sources Being absorbed → Fabric Pipelines
Azure Databricks
Unified Data + AI Platform (Partner)
Apache Spark-based platform with MLflow for experiment tracking, Unity Catalog for data governance, and Mosaic AI for model serving and fine-tuning. Microsoft's preferred partner for Spark-heavy data engineering and advanced ML workloads. Delta Lake (open format) is native — full interoperability with Fabric via shortcuts.
Positioning: Databricks and Fabric are not binary — they coexist and complement. Databricks for complex Spark pipelines and ML training workloads. Fabric for the BI, SQL, and self-serve consumption layer. Databricks Unity Catalog federates with Purview for unified governance across the estate.
FSI, Healthcare, Manufacturing ML-heavy workloads Coexists with Fabric
Azure Event Hubs
Real-Time Event Streaming
Fully managed, scalable event streaming service — the Azure equivalent of Apache Kafka. Handles millions of events per second. Supports the AMQP, Kafka, and HTTPS protocols. Events are retained for up to 7 days (standard) or 90 days (premium). Kafka API compatibility means no code change for existing Kafka producers.
Agentic relevance: Event Hubs is the streaming backbone for real-time agentic monitoring. In the pipeline monitoring system, ADF pipeline events route through Azure Event Grid into Event Hubs, where the SLA Watcher and Schema Drift agents consume them as a continuous stream — zero-touch architecture with no ADF code changes required.
Streaming / real-time Agentic event source IoT, Telco, Retail, FSI
Azure Event Grid
Event Routing & Reactive Architecture
Serverless event broker that routes events from Azure services (ADF, Blob Storage, Service Bus, custom sources) to subscribers (Event Hubs, Functions, Logic Apps, webhooks) — with filtering, transformation, and dead-letter handling. Enables fully reactive, event-driven architectures without polling.
Agentic relevance: Event Grid is the zero-touch bridge between ADF pipeline completion events and the agent monitoring layer. No code changes to existing ADF pipelines — Event Grid listens natively to ADF pipeline run events and forwards them. This is the "connect without touching" pattern for retrofitting agentic monitoring onto existing data estates.
Event routing Agentic architecture All industries
Azure Cosmos DB
Globally Distributed NoSQL Database
Multi-model (document, key-value, graph, column-family) globally distributed database with 99.999% availability SLA. Sub-10ms reads. Multiple consistency models. Native vector search capability (preview) making it relevant for embedding storage alongside operational data.
Agentic relevance: Cosmos DB is increasingly used as the operational memory store for agentic systems — storing agent state, conversation history, and retrieved entity data alongside the operational records agents need to act on. In FSI KYC scenarios, the client entity graph and case history live in Cosmos DB while agents query and update it.
Agentic memory / state FSI, Retail, Healthcare Global scale
Platform simplification — the Fabric value proposition Fabric changes the economics of data platform investment. The integration complexity that previously required significant engineering effort to solve — stitching together Synapse, ADF, Power BI, and Databricks into coherent pipelines — is now addressed by the platform itself. Investment shifts toward data products, governance design, and business outcomes rather than infrastructure engineering. For new greenfield programmes, Fabric is the default recommendation. For existing estates, the migration path from Synapse and ADF is clear and well-supported.

The Microsoft tools and partner frameworks that enable autonomous AI agents to plan, use tools, take actions, and coordinate across multi-agent systems.
Agentic AI on Microsoft Azure sits across three layers: orchestration frameworks that manage agent logic and state, Azure AI services that give agents capabilities (model inference, memory, tool use), and the data platform beneath that agents read from and write to. Microsoft's own Semantic Kernel sits at the centre — with LangGraph and LangChain as the leading open-source alternatives where finer control is required.

Semantic Kernel
Microsoft's Agentic Orchestration SDK
Microsoft's open-source SDK for building AI agents and multi-agent systems. Supports Python, C#, and Java. Native integration with Azure OpenAI, Azure AI Search, and Microsoft Graph. Provides planners (automatic task decomposition), plugins (tools agents can invoke), and memory connectors (Azure AI Search, Cosmos DB). AutoInvoke: agents automatically call the right plugin for a task.
When to choose: Microsoft-first organisations. .NET/C# development teams. Deep integration with Microsoft 365 and Teams required. Microsoft support and roadmap alignment critical (e.g., regulated FSI clients with vendor support requirements).
Microsoft-native FSI, Government, Healthcare .NET / C# teams
LangGraph
Open-Source Stateful Agent Framework
Graph-based state machine framework for building auditable, deterministic agentic workflows. Each agent is a node in a directed graph; edges represent state transitions. Full control over the agent loop — no magic, no hidden behaviour. Integrates with any LLM provider via LiteLLM or LangChain. Pydantic v2 for typed state schemas. LangSmith for observability and tracing.
When to choose: Where auditability is non-negotiable (statutory reporting, regulated processes). Where you need fine-grained control over agent state transitions. Where the team is Python-native and values explicit over implicit. This was the choice for the pipeline monitoring agentic system — deterministic state transitions were required for statutory risk context.
Maximum auditability Regulated environments Python teams
AutoGen (Microsoft Research)
Multi-Agent Conversation Framework
Microsoft Research framework for building multi-agent conversations. Agents communicate via natural language messages in a conversational loop. Supports hierarchical (GroupChat with Manager), sequential, and peer-to-peer patterns. AutoGen Studio provides a no-code interface for building and testing agent teams. Strong for research and exploration; less suited to production audit requirements.
When to choose: Research and experimentation. Rapid prototyping of multi-agent patterns. Scenarios where agents negotiating via natural language is desirable. Less suited to regulated production deployments where explicit state transitions and audit trails are required.
R&D / prototyping Microsoft ecosystem Not for regulated production
Azure AI Agent Service
Managed Agentic Platform (Preview → GA)
Microsoft's managed service for deploying and scaling AI agents — handles the infrastructure, tool integration, state persistence, and monitoring. Provides thread management (multi-turn conversations), built-in tools (code interpreter, file search, Bing grounding), and function calling. Integrates natively with Azure OpenAI models and Azure AI Foundry.
When to choose: When operational simplicity outweighs control requirements. When the client wants a managed service rather than managing LangGraph infrastructure. When rapid deployment of conversational agents (customer service, HR, internal knowledge bots) is the priority. Not yet the first choice for high-complexity, high-audit-requirement agentic workflows.
Managed / operational simplicity FSI, Retail, Enterprise Preview → GA trajectory
Copilot Studio
Low-Code Agent Builder
Microsoft's low-code/no-code platform for building conversational AI agents (previously Power Virtual Agents). Drag-and-drop topic design, native integration with Microsoft 365 Copilot, Dataverse for data, Azure OpenAI for generative responses, and Power Automate for workflow actions. Agents deploy to Teams, websites, SharePoint, and Teams channels. Now supports custom agent actions via connectors to external APIs.
When to choose: Non-technical business teams building internal productivity agents. HR bots, IT helpdesk agents, policy Q&A assistants. When the client has strong Microsoft 365 adoption and wants agents in the existing workspace without new infrastructure. Not appropriate for complex multi-agent architectures or regulated decisioning systems.
Low-code / citizen developer Productivity agents All industries
MCP (Model Context Protocol)
Emerging Open Standard for Tool Integration
Anthropic-originated open standard for how AI agents communicate with external tools, APIs, and data sources. Microsoft is adopting MCP as the standard for tool integration across Azure AI services and Copilot extensions. Enables standardised, auditable tool invocation — any MCP-compatible tool can be used by any MCP-compatible agent framework without custom integration code.
Architecture consideration: MCP functions as the "USB standard" for agentic tool integration — design tool integration layers to be MCP-compatible now, even where not all tools are MCP-native yet. This future-proofs agentic architectures as the ecosystem matures. Semantic Kernel, LangGraph, and Azure AI Agent Service are all moving toward native MCP support.
Emerging standard Future-proofing All industries
Framework selection — Director decision guide Regulated FSI / Healthcare / Government: LangGraph — maximum auditability, deterministic state, full audit trail. Microsoft-first enterprise / .NET teams: Semantic Kernel — native Azure integration, vendor support. Rapid prototyping / R&D: AutoGen — conversational flexibility, fast experimentation. Operational simplicity / managed: Azure AI Agent Service — infrastructure handled, less control. Business users / productivity: Copilot Studio — no code, Teams integration, fast time-to-value.
Section 03
GenAI, Models & Intelligent Services
The model layer — where natural language understanding, generation, document processing, and semantic retrieval happen.
Azure OpenAI Service
Foundation Model API — Microsoft's Core GenAI Offer
Microsoft's managed deployment of OpenAI's models on Azure infrastructure — GPT-4o (multimodal, best reasoning), GPT-4o-mini (fast, cost-efficient, ideal for classification and high-volume tasks), o1/o3 (extended reasoning for complex problems), DALL-E (image generation), Whisper (speech-to-text), and text embeddings (text-embedding-3-large/small). All models run within Azure's compliance boundary — data does not leave the customer's Azure tenant. Private endpoints, customer-managed keys, and Azure AD authentication. Enterprise SLAs.
Agentic pattern — deterministic-first: In high-volume agentic systems, use GPT-4o-mini for classification and routing decisions (fast, cheap), and GPT-4o only for complex reasoning tasks requiring judgment. This is the pattern that achieves $0.02/run cost efficiency. For regulated FSI: Azure OpenAI is the only acceptable option (data residency, compliance boundary, no data training on customer inputs).
All industries Primary choice: FSI, Healthcare, Government Data residency compliant
Azure AI Foundry
Unified AI Development Platform
Microsoft's central hub for enterprise AI development — model catalogue (OpenAI, Meta Llama, Mistral, Phi, Cohere, and 1,600+ models), prompt flow for orchestration, model fine-tuning, evaluation frameworks, and AI application deployment. The successor to Azure AI Studio, evolved into the enterprise GenAI programme hub. Integrates with Fabric for data, Purview for governance, and Azure AI Agent Service for agentic deployment.
Positioning in engagement: AI Foundry is where model strategy decisions are operationalised — which model for which task, how to fine-tune on proprietary data, how to evaluate outputs against business criteria, and how to deploy into production with full monitoring and governance. The CDO-facing framing: a unified control tower for the organisation's AI programme.
Model strategy hub FSI, Insurance, Energy Fine-tuning, evaluation
Azure AI Search
Enterprise Search + Vector Store
Fully managed search service combining keyword (BM25) + vector (approximate nearest neighbour) + semantic re-ranking in a single index. Hybrid retrieval is the most robust RAG pattern for enterprise knowledge applications. Supports multi-modal embeddings, RBAC on search results (user only retrieves content they're permitted to see), integrated chunking, and incremental indexing. Azure OpenAI embedding models integrate natively.
Agentic relevance: Azure AI Search is the retrieval layer for Enterprise Knowledge archetype — the RAG backbone for document Q&A, policy search, regulatory document analysis, and internal knowledge management agents. Hybrid retrieval (vector + keyword) outperforms pure vector search for enterprise content with precise terminology (regulatory text, medical records, legal documents).
RAG backbone FSI, Healthcare, Legal, Government Hybrid retrieval preferred
Azure Cognitive Services (AI Services)
Pre-Built AI Capabilities
Suite of pre-built AI capabilities: Document Intelligence (OCR, form extraction, contract analysis — key for insurance, legal, banking document workflows), Speech Services (speech-to-text, text-to-speech, speaker identification), Computer Vision (image classification, object detection, OCR), Language Services (NLP, entity recognition, sentiment, PII detection), Translator. These are the Cognitive Services Enablement archetype in practice.
Agentic relevance: Cognitive Services are typically the first layer in a document-processing agentic pipeline — Document Intelligence extracts structured data from unstructured sources (PDFs, scanned forms, contracts) before an agent reasons over that structured data. In regulated industries, Document Intelligence + Azure OpenAI for analysis is the standard pattern for document-heavy processes.
Document processing Insurance, Legal, Healthcare, Banking Preprocessing for agentic
Microsoft Phi (Small Language Models)
Efficient On-Device / Edge Models
Microsoft Research's family of small but capable language models — Phi-3-mini (3.8B), Phi-3-small (7B), Phi-3-medium (14B), Phi-3-vision (multimodal). Designed to deliver GPT-3.5-level reasoning at a fraction of the cost. Available via Azure AI Foundry, Ollama (local), and ONNX Runtime (edge/mobile). Phi-3-vision handles image + text inputs — relevant for document processing, quality control inspection.
Agentic relevance: Phi models are ideal for the deterministic-first design pattern — use Phi-3-mini for classification and routing tasks (nearly free to run), reserve GPT-4o for complex reasoning. In edge or offline scenarios (manufacturing shop floor, clinical device), Phi runs on-device without cloud connectivity. Proven in regulated manufacturing quality control systems where document and image analysis must operate without cloud connectivity.
Cost-efficient inference Manufacturing, Healthcare (edge) Offline / on-device
Microsoft Copilot for M365
Enterprise Productivity AI
AI assistant embedded across Microsoft 365 — Word, Excel, PowerPoint, Outlook, Teams, and SharePoint. Grounded in the user's Microsoft Graph data (emails, meetings, documents, chats) via Semantic Kernel and Azure OpenAI. Copilot Extensions allow organisations to connect custom data sources and build custom Copilot agents via Copilot Studio or code. The most widely deployed GenAI product in enterprise — large-scale rollouts are now measured in tens of thousands of licences across FSI, professional services, and retail sectors.
Deployment considerations: Copilot deployment requires more than licence procurement. It requires a data security and oversharing assessment (SharePoint permissions expose far more than organisations realise), a structured adoption strategy, a value measurement framework using Viva Insights telemetry, and a governance model for what employees can and cannot do with AI-generated content. The Copilot Governance Authority engagement pattern addresses all of these systematically.
All industries — widespread FSI, Professional Services Governance required
Section 04
Governance — Purview & the Trust Layer
The tools that make data trustworthy and AI auditable. In regulated industries, governance is not a phase two activity — it is the architecture.
Microsoft Purview
Unified Data Governance Platform
Microsoft's end-to-end data governance service — the horizontal capability that runs across every data and AI layer. Five core capabilities: Data Map (automated discovery and classification of data assets across Azure, M365, on-prem, and multi-cloud using 200+ built-in classifiers including PII, financial data, health data); Data Catalog (searchable, business-friendly catalogue of all data assets with business glossary, ownership, and lineage); Data Lineage (end-to-end lineage auto-discovered from ADF, Synapse, Fabric, Databricks, and SQL — showing exactly where each data element came from and what depends on it); Data Policy (access control policies that enforce who can access what data, applied automatically across services); Compliance Manager (regulatory compliance assessment against GDPR, BCBS 239, Solvency II, HIPAA, and others).
Agentic relevance: Purview is the governance layer for agentic systems in two ways. First, it provides the data lineage that agents need to understand the provenance and quality of the data they're acting on. Second, Purview's access policies govern what data agents are permitted to access — an agent operating within Purview-enforced policies can only access data the human user it represents is permitted to see. For the pipeline monitoring asset, the roadmap is to replace the static networkx lineage DAG with Purview's auto-discovered lineage from ADF metadata — dynamic, always current, no manual maintenance.
Mandatory: FSI, Healthcare, Government Lineage, cataloguing, compliance BCBS 239, Solvency II, HIPAA
Microsoft Entra ID (Azure AD)
Identity & Access Management
Microsoft's cloud identity platform — authentication (OAuth 2.0, OIDC, SAML), authorisation (RBAC, ABAC), Managed Identities for Azure services, Privileged Identity Management (PIM), and Conditional Access policies. For agentic systems: Managed Identities allow agents to authenticate to Azure services (Key Vault, Storage, Cosmos DB, Azure OpenAI) without storing credentials in code.
Agentic security pattern: Every agent should authenticate via a Managed Identity — no credentials in code, no secrets in environment variables. Entra ID + Purview policies together create a Zero Trust access model for agentic systems: agents only access what they're explicitly permitted to, enforced at the infrastructure level rather than the application level.
Zero Trust security All industries — mandatory Managed Identity for agents
Azure Key Vault
Secrets, Keys & Certificate Management
Centralised, HSM-backed secrets management — API keys, connection strings, certificates, and encryption keys. FIPS 140-2 validated hardware. Soft-delete and purge protection prevent accidental deletion. Azure Private Link for network isolation. Key rotation policies with automatic rotation for supported services.
Agentic architecture pattern: All agent credentials (Azure OpenAI API keys, database connection strings, external API keys) stored in Key Vault and accessed via Managed Identity — never in code, config files, or environment variables. This is the minimum secure configuration for any production agentic system in a regulated environment. Audited access logs show which agent accessed which secret and when.
Secrets management Regulated: FSI, Healthcare, Government Agent credential store
Azure Policy
Governance-as-Code
Built-in and custom policy definitions that enforce, audit, and remediate Azure resource configurations at scale. Built-in policies cover data encryption, network isolation, diagnostic logging, Purview integration, and AI service configuration. Initiative (policy set) groupings for regulatory standards (ISO 27001, NIST, PCI-DSS, Solvency II data requirements). Policy Assignment deploys governance at management group, subscription, or resource group level.
Agentic governance pattern: Use Azure Policy to enforce that all AI services deployed in the tenant must use private endpoints, customer-managed keys, diagnostic logging enabled, and Purview registration. This ensures every new agentic component meets governance requirements automatically, without relying on individual teams to remember compliance steps.
Governance-as-code FSI, Healthcare, Government Automated compliance enforcement
"In regulated FSI, Purview is not a feature you add to the data platform — it is the condition under which the FCA and PRA allow you to use AI in production. Lineage, classification, and access policy are not governance nice-to-haves; they are the auditable evidence that your AI system meets Consumer Duty and BCBS 239 requirements."
Section 05
Analytics, BI & Data Science
The consumption layer — where data products become decisions. From self-serve BI to ML model training and deployment.
Power BI
Business Intelligence & Self-Serve Analytics
Microsoft's BI platform — now native in Fabric as Power BI Fabric mode. DirectLake connectivity means reports query OneLake directly without import or scheduled refresh. DAX for measures. Power Query for data preparation. Row-level security for governed self-serve. Fabric Copilot in Power BI enables natural language report creation and DAX generation.
Agentic relevance: Power BI is the output layer for Data Analyst agents — agents that generate reports and visualisations on demand. Fabric Copilot in Power BI is also becoming an agentic capability in itself — users ask questions in natural language and the AI generates and executes the DAX or SQL query against OneLake.
All industries Self-serve BI persona Strongly preferred: FSI, Retail, Energy
Azure Machine Learning (Azure ML)
ML Lifecycle Management Platform
End-to-end ML platform: experiment tracking (MLflow integration), model registry, automated ML (AutoML), responsible AI dashboard (fairness, explainability, error analysis), managed compute for training and inference, and model deployment to managed endpoints (real-time and batch). Integration with Fabric feature stores and Databricks for data access.
Agentic relevance: Azure ML is the ML Ops layer for the ML & AI-Enabled Lakehouse archetype. It manages the lifecycle of ML models that agents use as tools — credit risk models, fraud detection models, churn propensity models. The Responsible AI dashboard in Azure ML provides the fairness and explainability evidence required for regulated model deployment.
ML Ops platform FSI, Healthcare, Manufacturing Responsible AI dashboard
Azure Stream Analytics
Real-Time Analytics on Streaming Data
Fully managed, serverless stream processing using SQL-like query language. Processes data from Event Hubs, IoT Hub, and Blob Storage. Sub-second latency. Built-in ML model scoring for real-time anomaly detection. Output to Power BI for live dashboards, Azure SQL, Cosmos DB, or storage.
When to use: Real-time KPI monitoring, IoT telemetry processing, fraud detection on payment streams, network monitoring in Telco. When Fabric Real-Time Intelligence (KQL-based) is not yet available or when the team is more comfortable with SQL. Stream Analytics fills the gap between event ingestion (Event Hubs) and agentic processing for simpler real-time analytics.
Real-time analytics Telco, Manufacturing, IoT Fraud detection, monitoring
Fabric Real-Time Intelligence
KQL-Based Real-Time Analytics (Fabric-Native)
Fabric's native real-time analytics capability — based on Kusto Query Language (KQL), the same query language as Azure Data Explorer. Handles high-volume, time-series, and log data with sub-second query response. Eventstream for no-code event processing. Activator for event-driven triggers and alerts. Native integration with Fabric data products and OneLake.
Agentic relevance: Fabric Activator is particularly relevant for agentic architectures — it monitors data patterns in real time and triggers automated actions (alert an agent, run a workflow, update a dashboard) when conditions are met. This is a lighter-weight alternative to a full LangGraph agent for deterministic, rule-based monitoring scenarios.
Fabric-native streaming Agentic triggers (Activator) Telco, Financial Markets, IoT

CI/CD & Project Management
End-to-end DevOps platform — Azure Repos (git), Azure Pipelines (CI/CD), Azure Boards (Agile project management), Azure Test Plans, and Azure Artifacts (package management). Native integration with Fabric workspace git integration, ADF pipeline deployment, and Azure ML model deployment pipelines. Supports Infrastructure-as-Code (Bicep, Terraform) deployment automation.
All industries CI/CD for data & AI
Azure Monitor & Application Insights
Observability & Alerting
Full-stack monitoring — infrastructure metrics, application performance, distributed tracing, log analytics (Log Analytics Workspace / KQL), and alerting. Application Insights instruments AI application telemetry — request rates, failure rates, latency percentiles. Integration with Azure OpenAI usage metrics (tokens, cost, latency) for GenAI cost monitoring.
Agentic monitoring: Every agentic system in production needs Azure Monitor for infrastructure-level observability (agent compute health, Event Hubs throughput, latency SLAs) alongside application-level tracing of agent actions and LLM calls. LangSmith (LangGraph's observability tool) complements Azure Monitor for agent reasoning traces.
Observability GenAI cost monitoring All industries
Azure Cost Management + Billing (FinOps)
Cloud Cost Optimisation
Native FinOps tooling — cost analysis by resource, department, project, and tag. Budget alerts. Cost anomaly detection. Reserved Instance and Savings Plan recommendations. Azure OpenAI token usage tracking by deployment, enabling cost attribution per agentic use case. Integration with Fabric capacity units monitoring.
AI cost governance: Most organisations deploying GenAI have no visibility of cost per transaction, per use case, or per business unit. Implementing token-level cost attribution across Azure OpenAI deployments — combined with the deterministic-first LLM invocation pattern — is the path from uncontrolled AI spend to $0.02 per transaction unit economics. FinOps for AI is increasingly a standalone workstream in data transformation programmes.
FinOps / cost control All industries AI cost attribution
Terraform / Azure Bicep
Infrastructure as Code
Terraform (HashiCorp, multi-cloud) and Bicep (Microsoft-native, Azure-only) are the two Infrastructure-as-Code choices for Azure. Both generate repeatable, auditable, version-controlled infrastructure deployments. Terraform has broader community support and multi-cloud capability; Bicep has tighter Azure API coverage and is Microsoft's strategic direction.
Agentic infrastructure pattern: Every production agentic system should have its infrastructure codified — in the pipeline monitoring asset, 8 Azure modules were Terraform-managed: Event Hubs, Event Grid, Key Vault, Storage, Azure OpenAI, Azure Functions, networking, and monitoring. IaC enables reproducible, auditable, environment-consistent deployment — essential for regulated industries where infrastructure configuration is part of the compliance audit.
Infrastructure as Code Regulated: FSI, Healthcare, Government Reproducible deployments

Selection principle — context over defaults The response to "which Microsoft AI tool should we use?" is never a single tool name. It is a structured set of questions: what is the current data engineering maturity, what are the regulatory compliance requirements, and where does the priority sit between maximum auditability and speed-to-value? The decision framework above provides the criteria. The right answer differs meaningfully between a Tier 1 bank (LangGraph, Purview, Azure OpenAI, maximum governance) and a FTSE 100 retailer (Fabric, Copilot Studio, SaaS-first for phase one). Fluency with these trade-offs, not just tool familiarity, is what drives sound architecture recommendations.
"The Microsoft Data & AI stack is not a menu — it is an architecture. Tools that appear similar (Fabric vs Synapse, LangGraph vs Semantic Kernel, Purview vs native RBAC) have fundamentally different implications for scalability, auditability, and cost at enterprise scale. The decision that matters is not which tools to use, but which trade-offs are acceptable for this organisation, in this regulatory context, at this moment in their data maturity journey."
